## 换了包名，请先卸载旧版

0.1.18 起包名从 `com.example.shareapp` 改为 `io.github.yichuanyc.yichuan`。两者是不同的应用，**不能互相覆盖升级**：

- 装着 0.1.17 及更早版本（旧包名）的设备，先卸载再装 0.1.18；
- 旧版本的安装包已全部下线，历史说明保留在 [CHANGELOG.md](CHANGELOG.md)；
- 应用内更新从 0.1.18 起重新工作，之后版本照常覆盖升级。

## 应用内更新

入口：设置 → 关于易川 → 软件更新。

- 从本仓库的 latest release 检查版本，按 `versionCode` 数字段比较
- 支持跨版本升级：只比较 latest 与本机，中间隔几个版本都能一步升到最新，不需要逐版接力
- 下载走前台服务，**多连接分段下载**（线程数可在软件更新页设 2/4/8/12/16，默认 8），支持断点续传与自动重试，通知栏可见进度、可就地取消
- 下载源可选三档：直连优先 / 加速优先（自建反向代理）/ 镜像优先（公共镜像，需确认一次）
- 安装前校验包名、`versionCode` 与**签名证书 SHA-256**，任一不符直接拒绝
- 只拉起系统安装器，不做静默安装；应用内不内置任何 token
- 更新日志取 release 正文，按分类条目排版展示，检测到新版本时自动弹一次，之后可在页面上随时重看

## 签名

发布包使用固定证书签名，SHA-256 指纹：

```
F7:E2:44:59:7E:00:15:CD:DA:1C:F2:A0:71:2C:57:FC:03:E9:36:73:0B:2B:3A:F6:1E:93:11:75:B4:80:10:20
```

签名变更意味着已安装用户无法覆盖升级，因此该证书长期不变。

## 更新日志规范

发布说明按分类条目书写，分类固定为「新增 / 改进 / 修复 / 注意」，无内容的分类整节省略。单条一句话，句末不加句号，只写用户可感知的变化。
